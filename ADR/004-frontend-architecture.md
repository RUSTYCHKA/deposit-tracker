# ADR-004 Frontend Architecture

## Status

Accepted

## Context

Frontend должен оставаться масштабируемым по мере добавления новых
финансовых продуктов, фильтров, калькуляторов и аналитики.

## Decision

Использовать Feature-Sliced Design (FSD).

Основные слои:

- app — инициализация приложения и глобальные providers;
- pages — страницы приложения;
- widgets — крупные самостоятельные UI-блоки;
- features — пользовательские действия;
- entities — бизнес-сущности;
- shared — переиспользуемый код.

## Consequences

### Positive

- Чёткое разделение ответственности.
- Удобное масштабирование проекта.
- Независимое развитие отдельных функций.
- Понятная структура для новых разработчиков.

### Negative

- Для маленького проекта структура может казаться избыточной.
- Требуется соблюдать правила зависимостей между слоями.

## Dependency Rules

Слои могут зависеть только от нижележащих слоёв:

app
↓
pages
↓
widgets
↓
features
↓
entities
↓
shared
