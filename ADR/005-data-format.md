# ADR-005 Data Format

## Status

Accepted

## Context

Проект должен работать как статический сайт, поэтому frontend
не должен зависеть от базы данных или API.

При этом данные банковских продуктов должны быть структурированными,
валидируемыми и пригодными для автоматического обновления.

## Decision

Использовать JSON как промежуточный формат хранения данных.

Python используется для:

- загрузки данных;
- валидации;
- нормализации;
- расчетов;
- генерации данных для frontend.

Pydantic используется для проверки структуры данных.

## Data Entities

Основные сущности:

- Bank
- Product
- ProductRate
- Inflation

## Consequences

### Positive

- Простая работа со статическим frontend.
- Данные можно хранить непосредственно в Git.
- Удобно просматривать изменения через Git diff.
- JSON легко генерировать автоматически.
- Pydantic позволяет обнаруживать ошибки до публикации сайта.

### Negative

- JSON не подходит для сложных запросов.
- История данных может значительно увеличить размер репозитория.
